# Инструкция для тестирования

Документ для проверки приложения перед вводом в эксплуатацию. Тестирование
проводится на **копиях** данных и на демонстрационных примерах, а не на
единственном рабочем файле.

Состав:

1. Подготовка окружения.
2. Автоматические тесты (быстрая проверка кода).
3. Проверка шаблона книги и формул.
4. Ручное тестирование по сценариям.
5. Проверка на целевом компьютере (Windows).
6. Чек-лист перед передачей пользователю.

Результаты фиксируйте в таблице из раздела 7: сценарий, результат, замечание.

---

## 1. Подготовка окружения

### 1.1. Установка

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

Требуется Python 3.10 или выше.

### 1.2. Проверка окружения

```bash
python scripts/doctor.py
```

Ожидаемый результат: все строки `OK`. Сообщение
«LibreOffice не найден» — не ошибка (PDF будет недоступен, останется DOCX).

### 1.3. Изоляция тестовых данных

**Всегда** используйте отдельный каталог, чтобы не затронуть рабочие данные:

```bash
# Windows PowerShell
$env:OTR_DATA_DIR = "C:\OTRegistry_test"

# Linux/macOS
export OTR_DATA_DIR=/tmp/otregistry_test
```

Для одного запуска без переменной окружения:

```bash
python run.py --data-dir /tmp/otregistry_test
```

### 1.4. Запуск

```bash
python run.py
```

Ожидается: в консоли адрес вида `http://127.0.0.1:8765/`, автоматически
открывается браузер.

## 2. Автоматические тесты

```bash
python -m pytest -q
```

Ожидается: **все тесты проходят**, ошибок нет.

Что проверяют тесты:

| Файл | Что покрыто |
|---|---|
| `tests/test_core.py` | расчёт сроков, пороги подсветки, работы с датами, нумерация, обязательные реквизиты, бумажный режим, хранилище |
| `tests/test_template.py` | структура книги, названия колонок, формулы, защита, справочники, демоданные, скрипт генерации |

Отдельный тест:

```bash
python -m pytest tests/test_template.py -v
```

Тест считается проваленным, если:

- изменилось количество колонок или их названия без обновления схемы;
- в формулах появился разделитель `;` (LibreOffice и Excel читают по-разному);
- книга создаётся без защиты;
- демоданные не проходят основные сценарии.

## 3. Проверка шаблона книги

### 3.1. Генерация файла

```bash
# с демоданными и защитой
python scripts/make_excel.py --demo --out demo.xlsx

# пустая книга без защиты (для сравнения)
python scripts/make_excel.py --no-protect --out empty.xlsx
```

Скрипт должен вывести отчёт: количество листов, строк, формул, наличие защиты
и пароль.

### 3.2. Что проверить в Excel

Откройте `demo.xlsx` в Excel:

| Проверка | Ожидаемый результат |
|---|---|
| Листы | 9 листов, порядок как в инструкции |
| Названия колонок | совпадают с шаблоном, без опечаток |
| «Инструктажи», колонки справа | «Дней до срока» и «Состояние» заполнены формулами |
| Значения формул | числа и текст после открытия книги (Excel пересчитывает) |
| Лист «Сводка» | числа в колонке «Значение», не пусто и не `#NAME?` |
| Подсветка | просроченные строки красные, ближайшие — оранжевые/жёлтые |
| Попытка изменить заголовок | Excel не даёт изменить: лист защищён |
| Попытка вставить строку | Excel не даёт: вставка строк запрещена |
| Статус | выпадающий список, постороннее значение не принимается |
| Лист «Инструкция» | читаемая памятка |

### 3.3. Проверка формул расчётом (без Excel)

Если Excel недоступен, формулы можно проверить вычислителем:

```bash
pip install formulas
python - <<'EOF'
import formulas, sys
sys.path.insert(0, 'src')
xl = formulas.ExcelModel().loads('demo.xlsx').finish()
sol = xl.calculate()
for key in sol:
    if 'СВОДКА' in key.upper() and key.endswith('!B2'):
        print('Всего запланировано =', sol[key].value[0][0])
EOF
```

Ожидается число, совпадающее с количеством запланированных записей.

## 5. Проверка на целевом компьютере

Выполняется на том компьютере, где будет работать специалист по ОТ.

### 5.1. Сборка

На Windows:

```bat
build.bat
```

Или вручную:

```bash
pip install pyinstaller
python scripts/build.py
```

Результат: папка `dist\instrOT\` с файлом `instrOT.exe`.

### 5.2. Проверка сборки

| Проверка | Ожидаемый результат |
|---|---|
| Запуск `instrOT.exe` двойным щелчком | Открывается браузер с приложением |
| Python на компьютере не установлен | Приложение всё равно работает |
| Интернет отключён | Всё работает: формы, печать, подсказки |
| Создание организации | Файл появляется в `%LOCALAPPDATA%\OTRegistry` |
| Закрыть и снова открыть | Данные на месте |
| Открыть книгу в Excel из папки данных | Книга защищена, формулы считаются |
| Ярлык на рабочем столе | Двойной щелчок запускает приложение |

### 5.3. Что проверить отдельно

- **Антивирус и Windows Defender** не блокируют запуск. При ложном
  срабатывании — добавить папку в исключения.
- **Русские пути и пробелы** в пути каталога данных работают.
- **Масштаб экрана** 125% и 150%: интерфейс читаем, ничего не обрезано.
- **Длинные ФИО** в таблицах и печати.
- **Принтер**: реальная печать бланка, проверка полей.

## 6. Регрессия после изменений

Перед каждым обновлением версии:

1. `python -m pytest -q` — все тесты проходят.
2. `python scripts/make_excel.py --demo --out check.xlsx` — файл создаётся,
   отчёт без ошибок.
3. Проверить три ключевых сценария на копии рабочей книги:
   - регистрация проведённого инструктажа по коду;
   - внесение бумажного бланка;
   - ручной режим Excel: правка, проверка, принятие.
4. Проверить открытие **старой** книги (созданной предыдущей версией):
   приложение должно предложить миграцию и сделать резерв.

Миграция проверяется так:

```bash
# 1. сохранить копию рабочей книги
# 2. запустить приложение новой версии, открыть организацию
# 3. в «Excel и резерв» выполнить обновление схемы
# 4. проверить: данные на месте, резерв создан, новые колонки пустые
```

## 8. Критерии готовности

Приложение считается готовым к эксплуатации, если:

**Технически:**

- все автотесты проходят;
- книга создаётся с правильными названиями колонок, формулами и защитой;
- защита снимается и возвращается в ручном режиме без потери данных;
- нет ошибок, приводящих к потере записей или смешению организаций;
- резервное копирование работает, восстановление проверено;
- сборка работает на компьютере без Python, без интернета.

**Организационно:**

- работодатель утвердил форму бланка и порядок регистрации (п. 88 Правил № 2464);
- проверена периодичность инструктажей для конкретных должностей;
- специалист по ОТ прошёл по инструкции пользователя весь обычный путь;
- проверена реальная печать на принтере;
- определено место для резервных копий на другом носителе.

**Не является блокером:**

- отсутствие LibreOffice (PDF не формируется, DOCX достаточно);
- отсутствие сканов документов;
- отсутствие отчётов сверх реализованных.

## 9. Как сообщить о дефекте

Приложите:

1. Что делали (последовательность шагов).
2. Что ожидали.
3. Что получилось фактически (текст сообщения, скриншот).
4. Версию приложения (внизу страницы) и версию схемы («Excel и резерв»).
5. Есть ли запись об ошибке в журнале действий.

**Не прикладывайте** реальные персональные данные в переписку: достаточно
обезличенного описания.
