# Журнал работ

История решений и изменений по проекту. Ведётся по ходу работы; записи не
переписываются задним числом — отменённые решения помечаются.

## 30.10.2026 — старт разработки

### Согласовано перед началом

- Упрощённая редакция 2.0: 1–2 пользователя, несколько организаций (отдельная
  книга Excel на каждую), без сервера в сети и без БД.
- Основной сценарий — формы в браузере на локальном сервере, данные сразу в `.xlsx`.
- Excel можно вести вручную через отдельный режим с последующей сверкой.
- Бумажный режим: заранее напечатанные пустые бланки с общим кодом `000-000`.
- Работы ведутся в GitHub `alexyalt/instrOT`, рабочая ветка `feature/mvp-v1`,
  промежуточные коммиты обязательны (см. `CONTRIBUTING.md`).

### Технические решения

| Решение | Причина |
|---|---|
| Flask + Jinja2 + небольшой JS | Минимальные зависимости, запуск из EXE, без Node.js |
| openpyxl для чтения/записи | Единственный источник данных — XLSX |
| Атомарная замена файла через временный файл | Не повредить книгу при сбое |
| Отпечаток SHA-256 перед записью | Обнаружить правки книги вне приложения |
| Msvcrt/fcntl блокировка | Не допустить двух одновременных писателей |
| Постоянные UUID записей | Сортировка строк не ломает связи и сверку |
| Дата рождения в снимке инструктажа | Обязательный реквизит (пп. 86, 87 Правил № 2464) |
| Расчёт сроков в Python, формулы в Excel — для отображения | openpyxl не пересчитывает формулы, кэш может быть устаревшим |
| Схема книги версионируется | Ручной Excel и обновления не должны молча ломать данные |

11. `migrations.py` — версия схемы, добавление недостающих колонок, резерв перед миграцией.
12. `rules.py` — требования ПП № 2464 в части инструктажей и сроков.
13. `tests/test_core.py` — 38 автотестов.

### Нормативные требования, заложенные в код

Источник: ПП РФ от 24.12.2021 № 2464, Правила обучения по охране труда.

- **п. 86** (вводный инструктаж): дата, ФИО, профессия (должность), число/месяц/год
  рождения, подразделение, ФИО и должность проводившего, подписи обоих.
- **п. 87** (первичный, повторный, внеплановый, целевой): дата, ФИО, профессия
  (должность), дата рождения, вид, причина (для внепланового и целевого), ФИО и
  должность проводившего, наименование ЛНА, подписи обоих.
- Повторный инструктаж — **не реже одного раза в 6 месяцев**; срок свыше 6 месяцев
  требует основания (реализовано предупреждение и требование основания).
- **п. 88**: порядок регистрации и форма документирования утверждаются работодателем —
  правовое основание собственных форм вместо журнала.

Отсюда изменения в коде: дата рождения стала обязательной при планировании и
регистрации; проверяется фактическая периодичность (индивидуальная или по организации),
а не только настройка организации; для внепланового и целевого обязательны и причина,
и ЛНА; значение по умолчанию — 6 месяцев вместо 12.

### Исправленные дефекты (найдены при проверке)

1. `prepare_org_dir` требовал необязательный параметр `name` — создание организации падало.
2. Фильтр `format_code` был объявлен только как глобальная функция Jinja — шаблоны падали.
3. `accept_changes` сохранял книгу при активной блокировке ручного режима и блокировал сам себя.
4. Новые строки без ID не попадали в отчёт сверки — добавлены как «новая строка без ID».
5. При связывании бумажного бланка с планом требовался инструктирующий, хотя он есть в плане.
6. Ограничение в 6 месяцев проверялось по организации, а не по фактической периодичности работника.
